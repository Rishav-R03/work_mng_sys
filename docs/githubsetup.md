# GitHub setup (OAuth sign-in + commit sync)

Work Tracker signs you in with a **GitHub OAuth App** and uses the same token to fetch your commits and merged PRs. You need two OAuth Apps if you want both local and production: one for `localhost`, one for Render. A GitHub OAuth App only allows one callback URL.

## 1. Create the OAuth App

1. Go to https://github.com/settings/developers → **OAuth Apps** → **New OAuth App**.
2. Fill in:
   | Field | Local | Production (Render) |
   |---|---|---|
   | Application name | Work Tracker (local) | Work Tracker |
   | Homepage URL | `http://localhost:8000` | `https://<your-app>.onrender.com` |
   | Authorization callback URL | `http://localhost:8000/auth/callback` | `https://<your-app>.onrender.com/auth/callback` |

3. Click **Register application**.
4. On the next page, copy the **Client ID**.
5. Click **Generate a new client secret** and copy it right away. GitHub shows it only once.

> The callback URL must match `BASE_URL` + `/auth/callback` exactly (same scheme, host, no trailing slash), or sign-in fails with a `redirect_uri` error.

## 2. Configure the app

### Local (`.env` in the project root)

```env
BASE_URL=http://localhost:8000
SECRET_KEY=<long random string>
GITHUB_CLIENT_ID=<client id>
GITHUB_CLIENT_SECRET=<client secret>
ALLOWED_GITHUB_LOGIN=<your github username>
GITHUB_SCOPE=read:user repo
```

Generate a secret key with:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Remove `DEV_LOGIN=1` (or set it to `0`) once GitHub sign-in works. Then run:

```powershell
.venv\Scripts\python -m uvicorn app.main:app --reload
```

Open http://localhost:8000 → **Sign in with GitHub**.

### Production (Render environment variables)

Same variables, with production values. See [Render + Neon](#4-render--neon) below.

## 3. Choosing the scope

`GITHUB_SCOPE` controls what the stored token can read.

| Value | Sees | Notes |
|---|---|---|
| `read:user repo` (default) | Commits and PRs in **public and private** repos | `repo` is broad: GitHub has no read-only private-repo scope for OAuth Apps. The token is stored encrypted, but it can also write. |
| `read:user` | **Public** activity only | Safest. Commits in private or employer repos won't appear. |

Things to consider before syncing employer repos:

- Your company may restrict third-party OAuth apps. For org repos you may need to be granted access: **Settings → Applications → Authorized OAuth Apps → Work Tracker → Organization access → Grant** (or request it from an org owner).
- Reports can end up shared outside the company. Commit titles and PR titles from private repos will appear in them.
- To remove access any time: https://github.com/settings/applications → revoke **Work Tracker**.

If you change the scope later, sign out and sign in again so GitHub issues a new token.

## 4. Render + Neon

Render's free filesystem is ephemeral and its free Postgres expires, so the database lives on **Neon**.

### Neon (database)

1. Create a free project at https://neon.tech.
2. Open **Connection details** and copy the connection string. It looks like `postgresql://user:pass@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require`.
3. The app converts the URL for SQLAlchemy automatically. Paste it as-is.

### Render (web service)

1. Push the project to a GitHub repository (private is fine).
2. In Render: **New → Blueprint** → pick the repo. It reads `render.yaml`.
   - Or **New → Web Service** manually: runtime Python, build `pip install -r requirements.txt`, start `uvicorn app.main:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips "*"`, plan Free, and set env var `PYTHON_VERSION=3.12.7`.
3. Set these environment variables:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Neon connection string |
   | `BASE_URL` | `https://<your-app>.onrender.com` |
   | `SECRET_KEY` | Auto-generated by the blueprint (or your own) |
   | `GITHUB_CLIENT_ID` | From the **production** OAuth App |
   | `GITHUB_CLIENT_SECRET` | From the **production** OAuth App |
   | `ALLOWED_GITHUB_LOGIN` | Your GitHub username |
   | `GITHUB_SCOPE` | `read:user repo` or `read:user` |

   Do **not** set `DEV_LOGIN` in production.
4. Deploy. The first deploy gives you the real `onrender.com` URL. If you guessed it in the OAuth App, update the OAuth App's homepage and callback URLs and the `BASE_URL` variable to match, then redeploy.
5. Check `https://<your-app>.onrender.com/healthz` returns `ok`.

The free service sleeps after about 15 minutes of inactivity. The first request after that takes 30–60 seconds. Sessions and data survive because they're in Neon and a signed cookie.

## 5. First sync

1. Sign in, open **Dashboard**, click **Sync GitHub**.
2. The first sync fetches the last 12 months in monthly windows and can take a minute or more. Later syncs only fetch since the last sync (with a 3-day overlap, de-duplicated).
3. Set your **timezone** under **Settings** (e.g. `Asia/Kolkata`) so commits land on the right calendar day.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `redirect_uri_mismatch` on GitHub | Callback URL in the OAuth App doesn't exactly match `BASE_URL/auth/callback`. |
| "GitHub OAuth isn't configured" on the login page | `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` missing or app not restarted after editing `.env`. |
| 403 "This tracker is private to its owner" | Your GitHub username doesn't match `ALLOWED_GITHUB_LOGIN` (case-insensitive, no `@`). |
| Sign-in works locally but loops or fails on Render | `BASE_URL` isn't the `https://` Render URL, so the secure session cookie isn't set. |
| "Stored GitHub token can't be read" | `SECRET_KEY` changed since you signed in. Sign out and sign in again. |
| "GitHub rate limit hit" | The search API allows about 30 requests per minute. Wait a minute and sync again. |
| Private-repo commits missing | Scope is `read:user`, or the org hasn't granted the OAuth App access (see section 3). |
| Commits missing for a repo | GitHub's commit search only indexes the default branch and ignores most forks. Commits must be authored with an email linked to your GitHub account. |
| Commits on the wrong day | Wrong timezone in Settings. |
